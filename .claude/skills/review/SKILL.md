# /review — двойное ревью

## Шаги

1. **Определи scope.**
   - Если передан аргумент (путь/модуль) — он и есть scope.
   - Иначе: незакоммиченные изменения + последний коммит (`git status --short`, `git diff HEAD --name-only`, `git log -1 --name-only`).
   - Если дифф пуст и аргумента нет — спроси пользователя, что ревьюить. Не ревьюй всю базу по умолчанию.

2. **Запусти обоих сабагентов ПАРАЛЛЕЛЬНО** — в одном сообщении два вызова Agent:
   - `security-reviewer` — передай список файлов scope и краткое описание изменения.
   - `unknown-unknowns` — тот же scope.
   Не жди одного, чтобы запустить второго.

3. **Сведи результаты.**
   - Дедуп пересекающихся находок.
   - КАЖДУЮ находку уровня CRITICAL/HIGH перепроверь сам по коду (открой файл:строку) — сабагенты ошибаются; в итоговый отчёт идут только подтверждённые.
   - Отсортируй по severity.

4. **Выведи отчёт:** таблица «severity / файл:строка / проблема / фикс» + краткий вывод (деплоить можно / сначала чинить).

5. **Предложи** занести подтверждённые находки в BACKLOG.md: CRITICAL/HIGH → 🔥 Now, остальное → 📋 Next. Код без запроса пользователя НЕ правь.
